## 1. 部署画像（先看清要在这台机器上跑什么）

| 组件 | 版本 | 端口 | 资源特征 | 来源 |
|---|---|---|---|---|
| Nginx | 1.24+ | 80（主站 + /api 反代）、8090（生成站点部署） | 常驻 ~20MB | 新增 |
| 后端 Spring Boot | Java 21 | 8123（仅本机监听，由 Nginx 反代） | 常驻 600MB–1.2GB | `pom.xml` |
| MySQL | 8.0 | 3306（仅 127.0.0.1） | 常驻 300–500MB | `application.yml` |
| Redis | 7 | 6379（仅 127.0.0.1，带密码） | 常驻 ~60MB | 缓存 + Session + 限流 |
| 无头 Chrome | google-chrome-stable | 无固定端口 | **峰值 300–600MB / 实例** | `WebScreenshotUtils` 截图封面 |
| Node.js + npm | 20.x | — | **构建期峰值 0.8–1.5GB** | `VueProjectBuilder` 跑 `npm install && npm run build` |
| 腾讯云 COS | 已有 bucket | 443 出网 | 图片/封面存储 | `CosManager` |
| DeepSeek API | 外部 | 443 出网 | 按 token 计费 | `application-local.yml` |

**内存账（决定买多大机器）**

```
常驻：OS 200M + MySQL 450M + Redis 60M + JVM 1.2G + Nginx 20M ≈ 2.0G
峰值：再叠加 Chrome 500M（截图）或 npm build 1.2G
→ 2C4G：常驻够用，峰值必须靠 swap + 串行（截图与构建不同时跑）
→ 4C8G：峰值放得下，体验最稳（贵约 1.5–2 倍）
```

**磁盘账（决定要不要数据盘）**

- 每个 Vue 工程：源码 + `node_modules` ≈ 200–400MB，构建产物 `dist` 只有几 MB
- 每次生成的应用代码都落在 `temp/code_output/{type}_{appId}`，**默认不清理**
- 结论：60G 系统盘 + **定时清理 14 天前的 `code_output`**（§7 的 cron），演示期足够；长期跑再加 100G 数据盘

## 2. 方案对比（4 选 1）

| 维度 | **A. 腾讯云轻量 2C4G（推荐）** | B. 阿里云 ECS + 云工开物券 | C. 轻量 + Docker Compose | D. 本地机器 + 内网穿透 |
|---|---|---|---|---|
| 首年成本（估） | ¥100–300 | ¥0–200（300 元券抵扣后） | ¥100–300 | ¥0 |
| 上线速度 | 当天 | 当天（需自配安全组/云盘/带宽） | 当天 | 1 小时 |
| 运维复杂度 | 低（原生 systemd） | 中（ECS 需要自己配网络与磁盘） | 中（要维护镜像） | 低但电脑必须开机 |
| 内存效率 | 高（无容器开销） | 高 | 比 A 少 300–500MB 可用内存 | 取决于本机 |
| 与现有 COS 协同 | **同账号同地域，最好** | 跨云（要迁 OSS 或继续走公网） | 同 A | 同 A |
| 适合场景 | 课程设计/简历/答辩 | 已有阿里云账号或想用券 | 想练习 Docker、频繁迁移 | 临时答辩、零预算 |
| 主要缺点 | 60G 盘要会清理；备案要时间 | 券的适用范围有限，超出要自付 | 2C4G 上容易 OOM | 断网/关机即下线，面试官打不开 |

**选择建议**

- 主推 **A**：你的 COS 在广州，服务器也买广州，内网直连、流量和延迟都最优。
- 如果你已经有阿里云账号且没买过 ECS：走 **B**，云工开物 300 元券能覆盖大部分首年费用（券的适用范围以权益专区为准，见 §3）。
- **C** 只在你打算长期折腾/多机迁移时选；本项目是「单体 + Chrome + Node」重负载，容器化收益不大。
- **D** 作为答辩当天的兜底（§12），不要当正式部署。

## 4. 推荐架构与端口规划

```mermaid
flowchart LR
    U[浏览器] -->|80/443| N[Nginx]
    N -->|/| S[前端 dist<br/>/var/www/wjx/dist]
    N -->|/api/**| B[Spring Boot :8123]
    N -->|:8090 /{deployKey}/| D[生成站点<br/>temp/code_deploy]
    B --> M[(MySQL 8 :3306)]
    B --> R[(Redis 7 :6379)]
    B -->|HTTPS| C[腾讯云 COS]
    B -->|HTTPS| AI[DeepSeek API]
    B -->|spawn| CH[Headless Chrome 截图]
    B -->|spawn| ND[Node npm build]
```

**端口/域名规划表**

| 用途 | 端口 | 对外地址示例（无域名） | 对外地址示例（有域名） |
|---|---|---|---|
| 主站（前端 + /api） | 80/443 | `http://1.2.3.4/` | `https://app.example.com/` |
| 生成站点部署 | 8090 | `http://1.2.3.4:8090/{deployKey}/` | `https://demo.example.com:8090/{deployKey}/` |
| 后端 | 8123 | **不对外开放**，只给 Nginx | 同左 |
| MySQL / Redis | 3306 / 6379 | **不对外开放**，只监听 127.0.0.1 | 同左 |

> 关键一致性：`APP_DEPLOY_HOST`（后端）与 `VITE_DEPLOY_DOMAIN`（前端）**必须写成同一个对外 8090 地址**，否则「部署成功」后按钮打不开、截图也会截到错地址。

**备案决策**

```
只给自己/面试官临时看 ──► 用 IP:端口，跳过备案（最快）
要一个像样的域名      ──► 大陆机器 + 域名 → 必须备案（7–20 工作日）
不想等备案            ──► 买香港/新加坡轻量（免备案），接受稍高延迟
```

## 5. 上线前代码改造清单（不改这 5 处，线上一定出问题）

| 编号 | 问题（已核实代码位置） | 现状 | 改法 |
|---|---|---|---|
| C1 | `pom.xml` 的 `spring-boot-maven-plugin` 配了 `<skip>true</skip>` | `mvn package` 只产出**瘦 jar**，`java -jar` 起不来（无依赖/无 Main-Class） | 删掉 `<skip>true</skip>`（或改 `false`）。IDEA 本地运行不受影响，只是打包会多花约 10 秒 |
| C2 | `AppConstant.java:22` `CODE_DEPLOY_HOST = "http://localhost:8090"` | 部署链接、截图目标地址都指向 localhost | 改为可配置：`@Value("${app.deploy-host:http://localhost:8090}")` 注入到 `AppServiceImpl` / `AppCoverServiceImpl`，或常量读环境变量 `APP_DEPLOY_HOST` |
| C3 | `AppGenerateView.vue:701` 硬编码 `http://localhost:8090/${deployKey}/` | 线上「访问部署网站」打不开 | 改用 `getDeployUrl(app)`（`src/utils/app.ts` 已按 `VITE_DEPLOY_DOMAIN` 生成） |
| C4 | `application-local.yml` 里是**明文 DeepSeek key + COS secretId/secretKey** | 上传服务器=密钥泄露；且 `spring.profiles.active: local` 写死 | 新建 `application-prod.yml`，全部用 `${ENV_VAR}` 占位；启动时 `--spring.profiles.active=prod`；密钥放 `/etc/wjx/env`（chmod 600）。**首次上线前请轮换这两个密钥** |
| C5 | 仓库只有 `create_table_user.sql` / `create_table_community.sql` / `create_table_material.sql` | **`app`、`chat_history` 两张表没有建表脚本**，新库跑不起来 | 本地执行 `mysqldump --no-data` 导出完整 schema（§6 Step 4），或用 MyBatis-Flex codegen 反推 |

**额外的「不必改但要知道」项**

- 素材上传上限已配 10MB（`application.yml`），**Nginx 必须同步 `client_max_body_size 12m`**，否则 413。
- 项目无 hibernate-validator，接口长度校验在 Service 里手写——不用额外装依赖。
- SSE 流式对话需要 Nginx `proxy_buffering off` + 长 `proxy_read_timeout`，否则打字机效果变成「一次性蹦完」。
- COS 图片地址是公网 URL；服务器与 bucket **同地域（广州）** 可避免跨区流量费。
- 会话存 Redis（`spring-session-data-redis`），单实例部署不用额外处理；将来多实例时天然共享会话。

## 6. 部署实施（Ubuntu 24.04 LTS，命令可直接复制）

> 约定：应用目录 `/opt/wjx`，前端 `/var/www/wjx/dist`，配置 `/etc/wjx/env`，运行用户 `deploy`。

### Step 0 · 买机器（10 分钟）

1. 登录腾讯云 → 完成**学生认证**（校园页：https://cloud.tencent.com/act/campus ）
2. 轻量应用服务器 → 地域选 **广州**（与 COS 同地域）→ 镜像 **Ubuntu 24.04 LTS** → 套餐 **2核4G / 5M / 500G / 60G SSD**
3. 记下公网 IP；控制台防火墙放行：**22、80、8090**（443 等配好证书再开）

### Step 1 · 系统初始化

```bash
ssh root@<公网IP>

# 时区 + 更新
timedatectl set-timezone Asia/Shanghai
apt update && apt upgrade -y

# 4G swap（2C4G 跑 Chrome + npm build 的保命配置）
fallocate -l 4G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
sysctl -w vm.swappiness=10 && echo 'vm.swappiness=10' >> /etc/sysctl.conf

# 运行用户
adduser --disabled-password --gecos "" deploy
usermod -aG sudo deploy
mkdir -p /opt/wjx /var/www/wjx && chown -R deploy:deploy /opt/wjx /var/www/wjx
```

### Step 2 · 安装依赖

```bash
# JDK 21（Ubuntu 24.04 源内自带；没有则用 Adoptium）
apt install -y openjdk-21-jre-headless || {
  apt install -y wget gnupg apt-transport-https
  mkdir -p /etc/apt/keyrings
  wget -qO- https://packages.adoptium.net/artifactory/api/gpg/key/public \
    | gpg --dearmor -o /etc/apt/keyrings/adoptium.gpg
  echo "deb [signed-by=/etc/apt/keyrings/adoptium.gpg] https://packages.adoptium.net/artifactory/deb $(. /etc/os-release && echo $VERSION_CODENAME) main" \
    > /etc/apt/sources.list.d/adoptium.list
  apt update && apt install -y temurin-21-jre
}

# MySQL 8 + Redis 7
apt install -y mysql-server redis-server

# Nginx
apt install -y nginx

# Node.js 20 + 国内镜像（后端会调用 npm install/build，默认 300s 超时）
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs
npm config set registry https://registry.npmmirror.com
node -v && npm -v

# Chrome（截图用）+ 中文字体（否则截图中文变方块）
wget -q https://dl.google.com/linux/direct/google-chrome-stable_current_amd64.deb -O /tmp/chrome.deb
apt install -y /tmp/chrome.deb fonts-noto-cjk
google-chrome --version
```

> 说明：Chrome 用官方 deb 而不是 `chromium-browser`（Ubuntu 24.04 的 chromium 走 snap，容器/服务账户下容易起不来）。`WebScreenshotUtils` 已带 `--no-sandbox`、`--disable-dev-shm-usage`，原生部署可直接用。

### Step 3 · 数据库与 Redis

```bash
# MySQL：建库 + 建应用账号（只允许本机）
mysql -uroot <<'SQL'
CREATE DATABASE IF NOT EXISTS wjx_ai_code_project DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
CREATE USER IF NOT EXISTS 'wjx'@'127.0.0.1' IDENTIFIED BY '换成强密码';
GRANT ALL PRIVILEGES ON wjx_ai_code_project.* TO 'wjx'@'127.0.0.1';
FLUSH PRIVILEGES;
SQL

# Redis：只监听本机 + 设密码
sed -i 's/^# requirepass .*/requirepass 换成强密码/' /etc/redis/redis.conf
sed -i 's/^bind .*/bind 127.0.0.1 ::1/' /etc/redis/redis.conf
systemctl restart redis-server
redis-cli -a '换成强密码' ping     # 期望 PONG
```

### Step 4 · 导出并导入完整表结构（本地执行）

```bash
# 本地（Windows git-bash）——注意必须带 --no-data，只导结构
mysqldump -uroot -p123456 --no-data --default-character-set=utf8mb4 \
  wjx_ai_code_project > schema.sql

# 上传到服务器
scp schema.sql root@<公网IP>:/tmp/

# 服务器
mysql -uroot --default-character-set=utf8mb4 wjx_ai_code_project < /tmp/schema.sql
mysql -uroot -e "use wjx_ai_code_project; show tables;"   # 期望含 app/chat_history/user/community_*/material
```

> 首次上线建议同时建一个管理员账号：密码字段是 `md5(明文 + "wjx")`（见 `UserServiceImpl`），SQL 里直接写死即可；上线后立刻改密码。

### Step 5 · 打包与上传

```bash

cd F:/wjx-ai-agentproject/wjx-ai-agent-project-back
~/.local/bin/mvn-msys -o -Dmaven.repo.local=C:/Users/王金鑫/.m2/repository \
  -Daether.enhancedLocalRepository.trackingFilename=_wjx.repositories -DskipTests package
```


## 10. 安全与运维基线

| 项 | 做法 |
|---|---|
| SSH | 禁用 root 密码登录（改密钥）；Lighthouse 防火墙只开 22/80/8090（443 后开） |
| 数据库 | MySQL/Redis 只监听 `127.0.0.1`；应用账号最小权限；root 只允许本地 socket |
| 密钥 | 全部放 `/etc/wjx/env`（chmod 600），仓库里删掉明文；**上线前轮换 DeepSeek 与 COS 密钥** |
| 上传 | 仅 JPG/PNG/GIF/WebP、≤10MB；`/api/material/file/**` 由 Spring 的 PathResourceResolver 防路径穿越 |
| 反代 | Nginx 传 `X-Forwarded-For`，后端评论/风控能拿到真实 IP |
| 限流 | 项目已有 Redisson 限流（发帖 5/分、评论 3/分、上传 20/分），无需额外网关 |
| 日志 | systemd 追加到 `/var/log/wjx/app.log`，用 logrotate 按周切割（§7.3 可加） |
| 监控 | 最低配：cron 每 10 分钟检查 `df`/`free`，超阈值写日志；想看得舒服可装 Netdata（占 ~100MB） |
| 升级 | 新 jar 先上传为 `app-new.jar` → `systemctl stop wjx` → 替换 → `start`；数据库结构变更前先 `backup.sh` |

## 11. 风险登记册

| 编号 | 风险 | 概率 | 影响 | 触发信号 | 对冲动作 |
|---|---|---|---|---|---|
| R1 | 2C4G 在「Vue 构建 + Chrome 截图」并发时 OOM | 中 | 后端被 OOM Killer 杀掉 | `dmesg | grep -i "killed process"`；`app.log` 突然中断 | 已加 4G swap；把截图与构建串行（构建期不刷新封面）；必要时升 4C8G |
| R2 | `npm install` 超过代码里的 300s 超时 | 中 | Vue 工程模式构建失败 | 日志出现「npm install 执行失败」 | 服务器 `npm config set registry https://registry.npmmirror.com`；先手动在 `temp/code_output` 里跑一次预热缓存 |

| R4 | 磁盘被 `node_modules` 撑满 | 高 | 生成/构建全部失败 | `df -h` > 80% | §7.1 每日清理 14 天前目录；演示前手动 `du -sh` 检查 |
| R5 | 密钥泄露（yml 明文已存在） | 中 | API 被盗刷、COS 被滥用 | 账单异常、COS 出现陌生对象 | C4 外置 + 轮换 + COS 设用量告警 |

| R7 | SSE 被 Nginx 缓冲，打字机失效 | 中 | 体验退化（功能仍可用） | 回复一次性出现 | 已在 §6 Step 8 配 `proxy_buffering off` |
